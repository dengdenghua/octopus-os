# 工作流修改原则

1. 保留已有节点 ID 和未涉及的输入，避免无关 diff 破坏用户调试历史。
2. 修改前识别加载器、条件编码、采样器、潜空间、解码器和保存节点的真实数据流。
3. checkpoint、VAE、LoRA、ControlNet 和放大模型只能从诊断返回的本机候选中选择。
4. 提示词、种子、步数、CFG、采样器、调度器、尺寸和去噪强度应作为显式输入记录，不能只写在对话总结中。
5. 图生图去噪强度越高，参考结构保持越弱；放大流程先确认显存和目标尺寸，避免无界分辨率。
6. 自定义节点缺失时给出节点名和来源要求，允许降级到核心节点时再提出替代图，不静默改变能力。
7. 保存前再次运行诊断；编辑后产生的新错误必须由本次修改解决或明确交还用户。
