# Echo OS 总体方案

> 当前基线：Echo OS、内建 Agent、桌面与发布工具共用一个仓库、一个 revision 和一个发行单元。

## 1. 产品定位

Echo OS 是面向个人设备和家庭服务器的 Agent 操作系统。核心交互不是“系统里安装一个聊天应用”，
而是让 Agent 成为桌面、文件、应用和系统能力的统一入口。

北极星场景：

1. 用自然语言查找、整理和理解本地文件；
2. 在审批和审计边界内跨应用执行自动化；
3. 统一管理本地模型、云模型、设备能力和数据权限；
4. 更新失败可回滚，服务异常可诊断，关键操作可复核。

## 2. 单仓架构

```text
frontend/                 唯一 Echo 桌面与工作台
    ↓ authenticated HTTP / IPC
appliance/                认证、文件、Hub、设备与系统能力
    ↓ appliance/agent_api/
runtime/                  内建 Agent 规划、执行、记忆与模型路由
    ↓
Linux / KWin / containers / storage
```

工程约束：

- `echo-os` 是唯一 Python distribution，包含 `appliance/`、`runtime/`、`tools/` 和
  `echo_runtime/`；
- `frontend/` 是唯一用户界面，不加载第二套 Agent WebUI；
- `appliance/agent_api/` 是设备层访问运行时的稳定领域边界；
- wheel、资源、Codex、桌面和镜像必须绑定同一个 Echo commit；
- CI 和本地构建都只读取当前 checkout，不接受第二份 Agent 源码或跨仓版本钉。

## 3. 分阶段路线

### 当前：NAS / 桌面闭环

- 登录、文件管理、应用 Hub、Agent 工作台和本地应用窗口统一在 Echo 桌面；
- Docker 与原生应用都通过受控目录和窄接口进入；
- Agent 在空闲时冻结应用侧渲染，KWin Effect 承担原生玻璃合成；
- 本地数据库、索引和模型服务作为可选能力接入，故障不阻断系统基本功能。

### 下一阶段：原生系统体验

- 完成 KWin Wayland Effect 的真机性能、缩放、多屏和输入矩阵；
- 补齐应用商城、账号、备份、迁移、通知、权限与更新体验；
- 在受控硬件上完成不可变系统、A/B 更新、Recovery 和安全启动验收。

## 4. 安全边界

1. 网页、文件内容和第三方应用输出默认视为不可信输入；
2. 高风险系统动作必须经过主体授权、一次性审批和审计；
3. 删除默认进入回收站，物理删除需要明确确认；
4. 外部容器和插件只能获得声明并批准的最小权限；
5. 发布只接受干净、已推送且在线可证明的 Echo revision；
6. dirty bundle 仅用于本地 QA，不能成为正式发行来源。

## 5. 完成定义

Echo OS 达到可交付状态需要同时满足：

- 开机直接进入 Echo 登录与桌面，不依赖开发服务器；
- Agent、文件、Hub、原生应用和系统设置使用同一账号与权限模型；
- 前端、后端、镜像、A/B、Recovery 和真机门绑定同一个源码身份；
- x86-64 与 arm64 目标设备完成安装、更新、回滚、断电恢复和备份恢复验收；
- 用户可理解系统做了什么、为什么做、用了哪些权限，并能撤销或恢复。
