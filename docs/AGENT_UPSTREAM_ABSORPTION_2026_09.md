## 一、执行一致性与稳定性

已接入本轮增量：

- 服务端提供历史时始终覆盖客户端历史，空日志也覆盖。直接嵌入方未提供服务端历史时
  保留兼容行为。
- 本轮权限模式、执行环境和网络选择通过线程上下文合并后，再做服务端规范化。
  `default` / `acceptEdits` 保持沙箱；被运营设置禁止的全权限不能通过模式字段恢复。
- 不可变 `ExecutionTask` 增加由宿主设置的实际引擎信息。原生与 Codex 入口显式绑定。
- Codex 工具目录与回调工作线程保留宿主请求、权限上限、资源截止时间及任务坐标。
  工具参数和可序列化 metadata 不能代替这些字段；不匹配的宿主线程/主体被拒绝。
- 扩大回归发现文件引用解析将输入列表当作 TurnParams 读取，导致用户消息创建异常
  被吞掉；统一了 metadata 读取的两种内部输入形状。

已存在、不能重复宣称新迁入的能力：Codex 流式事件合并、Windows 启动环境变量、
日志锁异常处理、安全的模型错误分类。仍需按最终接入范围验证其兼容性。

已补齐原生 ReAct、直接模型回复和 Codex 入口的执行记录：调用前持久化
`execution` 与有明确值的 `executionModel`，用实际引擎和递增 invocation 绑定。
重放拒绝跨引擎或过期模型坐标。原有隐藏 `execution_engine` 仍保留兼容用途。
未明确解析出的 Auto 不伪装成已知模型。

待完成：团队/项目外层驱动与成员执行服务的统一适配，以及这部分续跑、验证阶段的绑定。

## 二、跨引擎历史续接（原生/Codex 已接入，线上验收待完成）

- 复用 Echo 会话事件日志；不另建历史或长期记忆数据库。
- 增量接收边界必须由完成回合推进；根据真实内部会话恢复结果选择增量或近期完整历史。
- 限制轮数、正文和工具结果大小；不重放旧工具调用、不包含当前草稿和内部推理。
- 校验线程、账号、租户与当前 Session；历史是数据，不是新指令或权限。
- 已补齐本地事件协议与执行坐标，并适配上游投影。晚到的转向会重建宿主 Session，
  因此同轮去重读取持久化接收回执，不信任客户端 metadata 中的接收标记。
- 账号与租户以内部日志字段保存，保持公共 TurnParams 序列化排除；已验证不同主体的
  真实落盘记录会拒绝进入历史。旧日志仍依赖入口已有的线程访问控制。
- 隐私模式仍拒绝云引擎，不得通过历史恢复产生隐含外发。
- 模拟协议已验证 Codex 恢复成功、新建、原会话明确不存在时的真实请求载荷；
  未完成真实云端原生/Codex 互切验收，也没有声称 OpenCode 已接入。

## 三、模型调用控制（部分接入）

已接入：Codex 使用共享 `web_fetch` 时返回有界正文与 `answer_pending=true`，
交由当前模型回答，避免再调用辅助供应商。URL 安全检查与宿主工具审批仍在前置路径。
原生和旧嵌入调用保留辅助问答。工具描述同步说明两种结果形状。

已接入自动/手动历史压缩策略：最近实际执行为 Codex 时使用本地规则摘要，
不隐含调用宿主摘要模型；原生与未知旧记录保留已有行为，显式自定义摘要器保持优先。
12 项组合验证了真实日志压缩、最近轮次保留、通知和辅助模型调用次数。

已接入宿主 `approval_router` 与 `background_router` 独立注入；旧构造方继承既有路由，
显式 `None` 不会回退借用对话模型。原生、CLI 和 Codex 工具自动审核接入审核服务；
独立审核默认使用自身路由的模型，不将 Codex 模型 ID 传给宿主供应商。
自动审核服务缺失或失败时拒绝执行；可选的附加 Guardian 审查仍保持既有“只能收紧”语义。

已接入 `execution.background_model_calls` 严格布尔配置（也可为 null 保持当前默认）。
关闭后跳过定时模型反思、提示词进化、自动进化与实验调优；模型入口再次检查策略，
已注册的回调不能因排队而忽略关闭。记忆蒸馏保留确定性的本地维护路径。
此设置不取消已在运行的模型请求，也不关闭前台安全审查、用户对话、显式用户定时任务。
示例配置已补充，修改后需重启服务；尚无新增桌面开关。
记忆蒸馏、提示词/实验 mutator 使用后台路由；反思和 deep_evolve 保留原有模型服务，
但自动入口受上述策略控制。没有宣称所有辅助调用已统一到一条路由。

当前工作区已有原生/Codex 包按需导出，本轮补验公开接口身份、星号导入与轻量导入，
并将其回归纳入源码门禁。Windows 上每种情况 5 个独立 Python 进程取中位数：

| 轻量模块 | 按需加载 | 强制解析当前包全部公开导出的对照 | 已加载模块数（按需/对照） |
| --- | ---: | ---: | ---: |
| `runtime.core.cerebrum.react_types` | 20.9 ms | 818.1 ms | 91 / 749 |
| `runtime.execution.codex_backend.types` | 24.5 ms | 927.2 ms | 91 / 854 |

计时为进程内 `perf_counter` 覆盖 import 和可选 `getattr(package, name)` 遍历；
不含进程创建，不是旧发布版本或桌面启动时间的比较。完整 planner 的延迟实例化仍待适配。
不能仅因切换对话引擎，就声称整个系统没有后台费用或网络请求。

- 公共层接受宿主指定的引擎与工具预算，Codex 目录收敛为 128 项；模型参数不能改变

- 抽出 `tool_engine/role_instructions.py` 复用身份、模式、记忆与可信注册表选中技能；
  Codex 包装追加专属能力限制，并预留字符预算，超长角色内容不能截断该限制。
- 同轮回调保留执行器维护的读文件证据、快照与写入租约；传输字段不能伪造这些状态。
  使用真实执行器和临时文件验证：未读旧文件时拒绝覆盖，读取后下一次回调可正常写入。
- 连接取消不会放弃已进入原生执行器的操作或提前释放调用锁。共享 broker 关闭后拒绝
  新调用，Codex 生命周期退出时撤销并排空已接纳调用，包括子进程关闭异常路径。
- 新回归复现审核回调误继承其他 Session 的问题，已修复为恢复宿主 Session 后审核，
  防止独立审核模型读取错误的账号、租户或任务上下文。
- 已接入临时认证 MCP 传输 `tool_engine/host_mcp.py`：随机回环端口、内存令牌、单次生命
  周期、有界 HTTP 请求；拒绝匿名、外部 Host/Origin、过期任务和关闭后的调用。通道必须
  匹配 broker 已捕获的宿主任务、权限对象、资源对象及 Session，不能仅凭相同账号/线程名
  换一份授权。回调显式恢复任务、Session 与能力租户上下文，关闭时排空在途操作。
- MCP 真实文件回归复现了本仓只读任务的 sandbox 参数误拒绝读取，已从上游吸收针对性
  修复：读取使用授权读范围，写入继续要求写范围；保留本仓额外的 NAS 路径与服务工具检查。
- OpenCode 后端适配组件已迁入 `execution/opencode_backend.py`：隔离子进程环境、账号/
  租户/线程状态分区、增量事件、恢复与新建历史载荷、终态校验、停止和进程树回收。
  本仓要求显式配置绝对执行路径与 Zen 模型；不继承 PATH 中的其他安装，不启用上游匿名
  默认模型，不把 OpenCode 内置网页工具作为绕过宿主审批的入口。隐私模式在进程启动和
  提交/轮询前拒绝云推理。HTTP 200 不等于完成，错误和不完整输出不能签发成功回执。
- 已接入 OpenCode 宿主角色执行入口：实时回合的显式 `executionEngine=opencode`
  现在经过统一 `ExecutionSupervisor`，使用同一宿主请求、权限、取消、转向和持久化执行坐标，
  再进入 OpenCode 流式适配器；新增回归验证身份、租户、会话和 `turn/execution/updated` 事件。
  前端选中 OpenCode Zen 模型时会把 `execution_engine=opencode` 送入宿主，并保留普通模型的
  Echo/Codex 路由；真实官方进程和 Zen 云端仍未验收。
  此功能使用项目现有 `mcp` 可选依赖，NAS 基础安装不因它增加常驻服务。CI 增加锁定 MCP
  依赖的专门回归步骤；未配置可选引擎时不启动通道或子进程。
- 不复制上游本地宿主的默认 OpenCode 策略；NAS 的默认路由、隐私限制与显式模型选择优先。
- 免费云模型不是本地模型；程序安装在本机也不构成离线证明。
