# 本机模型推荐与启用

入口：系统设置 → 模型与 Codex → 高级工具 → 本地模型推荐。

## 一键部署本地 AI

点击“部署本地 AI → 检查部署方案”，服务端从内置目录按当前资源选取首个可运行模型（不自动采用热门社区目录），显示模型、预计内存、环境下载大小、模型下载估算、磁盘余量和实际存储位置。管理员点击“确认部署”后，后台自动完成：

1. 下载固定版本 Ollama 独立运行包，校验代码中固定的 SHA-256，再解压到暂存目录，完整后原子移入版本目录。
2. 启动独立回环服务 `127.0.0.1:11435`，设置 `OLLAMA_NO_CLOUD=1`、4K 上下文、单并发、最多驻留一个模型。
3. 下载模型，执行本机文本、工具和视觉能力验证。
4. 验证成功后启用托管服务；勾选“验证后设为默认”时，由当前管理员会话接入共享模型配置。未勾选则保留原默认模型。

默认位置为 Echo 数据目录下的 `local-ai/`，与 `ECHO_DATA_DIR` 配置一致；界面展示服务端真实路径，不能通过请求传入任意安装路径。现有 Ollama 的运行程序和权重不会被搬迁或替换，托管安装有自己的模型目录。首次部署可能重复下载已有服务中的同名模型。显式设置了其他 `OLLAMA_BASE_URL` 时会阻止托管部署并提示处理覆盖配置。

环境包固定为官方 `v0.33.3`。支持 Windows x64/ARM64、Linux x64/ARM64；Linux 解压需要系统 `zstd`（已加入 Echo NAS 镜像的软件包清单，旧系统需补装）。macOS 暂时继续使用已有本机模型服务。不会自动安装 GPU 驱动或额外的 AMD ROCm 包，硬件是否加速仍取决于对应驱动和运行包。

安装方式依据 [Ollama Windows 独立 CLI 文档](https://docs.ollama.com/windows)、[Linux 手动安装文档](https://docs.ollama.com/linux)；包大小和摘要来自 [官方固定版本发布页](https://github.com/ollama/ollama/releases/tag/v0.33.3)。本机环境配置参见 [Ollama FAQ](https://docs.ollama.com/faq)。

### 进度、重启与失败

- 环境下载展示字节进度，模型下载及验证展示阶段状态。方案十分钟有效，确认时再次检查磁盘余量；模型大小仍是估算，磁盘预算包含暂存及系统余量，不是磁盘配额。
- 离开设置页后后台继续准备。同一浏览器标签页、同一用户返回设置页时，可以继续原先授权的默认模型接入；关闭整个浏览器或切换用户后，不会替其他用户自动切换模型。接入失败可手动重试。
- 已启用的托管服务随 Echo 后端启动、关闭。这里的自启是跟随 Echo 生命周期，未另行创建 Windows 开机服务或修改系统 systemd；设备开机自动运行仍依赖 Echo 自身的自启设置。
- 准备状态落盘。后端中途重启后会提示重新部署，不会暗中继续下载；Ollama 已下载的权重可复用。验证缓存仍有 20 分钟时限，重启或过期后需重新验证才能接入默认模型。
- 安装校验、解压、启动、下载、验证任一步失败均不会切换默认模型。已完成的安装和权重保留以便重试。端口被其他服务占用时失败，不接管其他进程；异常退出留下的旧进程可能需要管理员处理。
- OS 文件锁阻止多个 Echo 进程同时管理托管目录；同一进程的部署与已有下载/验证任务互斥。这不是整个设备所有模型服务的全局资源隔离。

新增管理员接口：`POST /api/cookbook/deployment/plan`（tag）、`POST /api/cookbook/deployment/start`（plan_id）、`GET /api/cookbook/deployment`。方案由服务端生成，不接受客户端自定义安装包 URL、摘要或命令。

验证覆盖方案只读、权限、过期、资源变化、并发、安装包摘要及重定向、解压路径、失败落盘与启用顺序，以及界面确认、取消默认选择和用户隔离。自动化测试使用小型伪安装包和伪模型服务；尚未在本机下载实际运行包/大模型，也未完成 Linux/ARM64 实机部署验收。

## 操作流程

1. 自动检测当前可用内存和支持的 GPU 空闲显存，预留系统/NAS 资源。可选择 4K、8K、16K、32K 上下文估算预算。
2. 未安装的模型点击“下载并验证”；已安装的模型点击“本机验证”。当前自动准备流程使用本机 Ollama；LM Studio 等服务仍走扫描和手动导入。
3. 后台验证实际 OpenAI 兼容对话接口：固定文本、不会执行的测试工具调用，以及支持视觉模型的合成色块图。显示文本首个测试请求的总耗时和能力验证结果。
4. 验证通过后点击“设为默认”：持久化独立模型连接，注册路由，再保存当前用户的共享模型配置。桌面和 Agent 读取同一配置，后续任务采用新默认模型。

下载、验证和设为默认是不同状态。文本失败、配置写入失败、路由注册失败不会切换默认模型；工具/视觉测试失败不会被登记为支持相应能力。只支持文本的模型可用于对话，不应据此认为它适合执行 Agent 工具任务。

## 隐私和失败处理

- 本机准备流程只允许回环地址，不经过环境代理、不跟随重定向。不会读取 NAS 文档、照片、文件名或历史会话。
- 检查模型目录、实际权重元信息和版本摘要；Ollama 声明的远端模型不能通过本机验证。
- 下载由用户明确点击触发，会让 Ollama 联网获取权重。隐私模式不自动刷新 HuggingFace 目录，已有目录缓存仍可使用。
- 下载完成后重新检查当前资源预算，资源不足则停止自动加载验证；已经驻留的同版本模型可复用。
- 验证结果保留 20 分钟，绑定连接地址和模型摘要。启用时重新核对摘要，服务变化、结果过期或模型替换后需要重验。
- 每个 Agent 服务进程同时准备一个模型，避免多个下载/加载任务争用 NAS 资源。进程重启后验证状态需要重建；Ollama 自身可能仍保留已下载的权重。

## 估算边界

推荐使用可用资源快照，不是性能保证或操作系统资源隔离。CPU 模型会对较大的活跃参数量降权；多张显卡不直接累加显存。上下文预留是通用估算，不是按模型架构精算的 KV cache。界面的上下文选择仅用于估算，导入连接按保守的 4K 上下文登记，Ollama 运行时参数仍由 Ollama 管理。

AMD/Intel GPU、容器资源限制、磁盘空间与 NAS 后台负载尚未做到完整感知。工具和色块测试只是能力冒烟测试，不能证明复杂任务质量。第三方本机服务内部行为仍需要管理员信任；整机完全断网需额外的操作系统网络隔离。

## 接口与验证

- `GET /api/cookbook/snapshot?context_tokens=4096`：资源、推荐、已安装模型、准备状态和验证结果。
- `POST /api/cookbook/pull`：下载后自动验证；`POST /api/cookbook/verify`：验证已安装模型。两者需要管理员或操作员权限。
- `POST /api/config/local-models/activate`：管理员将服务端保存的已验证结果注册为连接；客户端随后调用现有共享模型配置接口。

覆盖包括伪 Ollama 响应、远端地址、代理/重定向配置、无效目录、远端模型别名、文本/工具/视觉结果、资源不足、版本变化、验证过期、并发准备、持久化回滚，以及前端保存失败与用户切换。测试不下载真实权重；真实模型速度和质量须在对应设备上验证。
